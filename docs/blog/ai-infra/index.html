系列路线图 ​

本系列以 SGLang 为主线，按它的架构来组织：一个请求从 HTTP 进来，经过调度、显存管理、模型执行，再扩展到多卡和多实例。每一层对应几篇文章，每篇都对准代码里的一个具体组件。

编号就是阅读顺序：先跑起来、看清全貌，再沿着请求的路径往下走，最后走出单个实例。

  • 🖥️ 本地：RTX 2070 8GB + WSL2，跑通流程、读源码、调试脚本
  • ☁️ 云上：按小时租 GPU，出正式 benchmark。4090 起步，测多卡和 Hopper 特性时才上 A100 / H 系列

为什么从 SGLang 开始 ​

  • RadixAttention、调度器、结构化输出、投机解码、PD 分离、Router 都在同一个代码库里，一条主线能从头讲到尾
  • 代码以 Python 为主，调度逻辑集中在 Scheduler 里，读得动，「原理浅析」可以直接贴源码
  • 微调也接得上：verl 等 RL 框架用 SGLang 做 rollout 引擎，最后做 GRPO 时，前面的调优经验能直接用

vLLM 不单独开线，放在「生态与对比」里。等读者理解了 SGLang 的每一层，再做同条件横评。

贯穿全系列的约定 ​

  • 性能文章一律用 python -m sglang.bench_serving，数据集固定为 random、sharegpt、generated-shared-prefix 三种，参数写进文章，后文好对比
  • 模型档位固定：本地用 1.5B 级 FP16 小模型，云上用 8B 级稠密模型，MoE 文章换 30B-A3B 级
  • 每篇在 EnvCard 里写 SGLang 版本和 commit，不同版本的结论不混用
  • 2070 的硬限制照实写：Turing（sm75）不支持 BF16、FP8、FA3，部分量化 kernel 要求 sm80+。本地跑不了的特性写明原因，再到云上补测

前置：跑起来，看清全貌 ​

先把环境搭好、模型跑起来、学会怎么量，再用一篇把整个架构过一遍，后面每一篇都会回到这张图上。

#主题环境状态
0从零开始：在 8GB 显卡上搭环境、跑模型、做压测（WSL2 + Docker、Turing 上的 --dtype half、bench_serving 与 TTFT / TPOT / ITL）🖥️ 本地草稿
1架构总览：一个请求经过哪些进程（TokenizerManager → Scheduler → ModelRunner → Detokenizer），各层之间怎么传数据🖥️ 本地计划中

调度层：Scheduler ​

决定每一步哪些请求进 batch、做 prefill 还是 decode。吞吐和延迟的取舍大多在这里。

#主题环境状态
2调度循环：continuous batching、chunked prefill 与调度策略（lpm / fcfs）☁️ 云上计划中
3CPU 开销与 overlap scheduler：GPU 为什么会等 CPU🖥️ 本地 + ☁️ 云上计划中
4结构化输出：grammar backend 怎么接进调度和采样，xgrammar 的开销有多大🖥️ 本地计划中

显存与 KV 缓存层 ​

KV Cache 怎么分配、怎么复用、放不下时去哪。决定了能同时服务多少请求。

#主题环境状态
5显存账本：权重、KV Cache 内存池、CUDA Graph 各占多少，--mem-fraction-static 到底在切什么🖥️ 本地计划中
6RadixAttention：多轮对话、共享 system prompt、few-shot 下的前缀命中率实测☁️ 云上计划中
7HiCache：GPU 放不下的 KV Cache 溢出到内存，8GB 显卡上收益有多大🖥️ 本地 + ☁️ 云上计划中

执行层：ModelRunner ​

真正在 GPU 上跑前向的地方：kernel 选择、图捕获、量化、投机解码都在这一层。

#主题环境状态
8Attention backend 与 CUDA Graph：FlashInfer / Triton / FA3 的取舍🖥️ 本地 + ☁️ 云上计划中
9量化：FP8 / AWQ / GPTQ / KV Cache FP8，各自对显卡架构的要求🖥️ 本地 + ☁️ 云上计划中
10投机解码：EAGLE 系列参数怎么调，接受率随 batch size 怎么变☁️ 云上计划中
11Multi-LoRA 服务：一个 SGLang 实例挂多个适配器🖥️ 本地 + ☁️ 云上计划中

并行层：一个实例跨多卡 ​

模型或流量超出单卡时，怎么切分权重、请求和专家。

#主题环境状态
12稠密模型多卡：TP 与 DP 的配置与扩展性☁️ 云上计划中
13MoE 多卡：DP Attention 与 EP☁️ 云上计划中

集群与运维层：走出单个实例 ​

多个实例怎么分流量、拆阶段、上 K8s，以及怎么看清线上在发生什么。

#主题环境状态
14可观测性：--enable-metrics + Prometheus + Grafana 看板🖥️ 本地计划中
15多副本与 Router：cache-aware 负载均衡 vs 轮询☁️ 云上计划中
16PD 分离：prefill 和 decode 拆到不同实例☁️ 云上计划中
17K8s 部署 SGLang 与自动扩缩容🖥️ 本地 + ☁️ 云上计划中

生态与对比 ​

SGLang 之外：和 vLLM 横评，以及微调、RL 怎么接回 SGLang。

#主题环境状态
18SGLang vs vLLM 横评：同模型、同硬件、同压测脚本☁️ 云上计划中
19LoRA / QLoRA 微调 → SGLang 部署闭环（Unsloth / LLaMA-Factory）🖥️ 本地计划中
20小规模 GRPO：verl + SGLang rollout☁️ 云上计划中

写作约定

每篇遵循同一结构：要解决的问题 → 最小可运行示例 → 关键参数 → 实测数据 → 踩坑记录 → 原理浅析，文末附环境版本与云上花费。
